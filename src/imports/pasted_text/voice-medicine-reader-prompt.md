Use this revised Figma prompt:

Design a complete modern accessibility-first Android application called [App Name] — Voice Medicine Reader & Assistant for elderly people, low-literacy users, visually impaired users, and people who have difficulty reading medicine strips, labels, dosage, expiry dates, warnings, and medicine information. CORE PRINCIPLE: THE ENTIRE APPLICATION MUST WORK THROUGH VOICE ONLY. The user should never need to type, tap, swipe, select, or navigate manually. Voice is the only input method. The screen should display all information visually in large, highly readable text, but every displayed instruction, result, warning, notification, and option must also be spoken aloud. Everything the user says must be understood as a voice command or answer. The app should continuously guide the user through voice interaction. Core journey: OPEN → SPEAK → AUTO-DETECT LANGUAGE → VOICE PROFILE SETUP → VOICE LOGIN → VOICE COMMAND → SCAN → IDENTIFY → VERIFY → UNDERSTAND → SPEAK + DISPLAY → SAVE HISTORY → NOTIFY → CAREGIVER. VOICE-ONLY DESIGN RULES: Remove all text-input fields. Remove normal touch-based navigation. Do not require buttons to be tapped. Do not require keyboard input. Do not require the user to select options manually. Every action must have a voice equivalent. The interface can visually display buttons and options for clarity, but the user activates them by speaking. Example: instead of tapping Scan Medicine, the user says “Scan medicine.” Instead of tapping Yes, the user says “Yes.” Instead of typing a medicine name, the user says it. Instead of selecting a language, the user speaks naturally and the app detects the language automatically. VOICE + DISPLAY: Every screen must simultaneously provide visual information and spoken feedback. When the app displays “Please scan the medicine,” it must also say it aloud. When the app displays a medicine name, it must speak the medicine name. When the user asks a question, the answer must be displayed and spoken. When the app asks a question, the user answers by voice. Use large typography, high contrast, simple layouts, large visual icons, clear status indicators, audio feedback, and subtle animation. 1. APP OPEN: When the app opens, immediately speak: “Hello. How can I help you?” Display the same message in large text. Do not require the user to tap anything. The app immediately enters voice-listening mode. Example commands displayed and spoken: “Scan medicine”, “Show my medicines”, “Help”, “Settings”. The user can simply speak one of these commands. 2. LANGUAGE DETECTION: On first launch, automatically start listening and say: “Please say a few words in the language you normally speak.” Do not show a language-selection list. The user speaks naturally, for example Tamil, Hindi, Telugu, Kannada, Malayalam, English, or another supported language. Automatically detect the spoken language. Display the detected language and speak: “I detected Tamil. I will speak to you in Tamil.” Then ask by voice: “Is that correct?” The user responds “Yes” or “No.” If incorrect, ask the user to speak again. 3. VOICE PROFILE SETUP: Ask everything through voice. Say: “What is your name?” User speaks their name. Display and repeat it. Say: “What is your age?” User speaks their age. Say: “Please tell me your mobile number.” User speaks the number if known. If the user says “I don't know my number,” do not block them. Create a secure device-based profile. Never require typing. 4. VOICE OTP LOGIN: If a phone number is provided, say: “I have sent an OTP to your phone. Please tell me the OTP.” The user speaks the OTP. Display the recognized digits and read them back for confirmation. User says “Confirm” or “Try again.” Do not require keyboard entry. 5. VOICE PRIVACY CONSENT: Say: “I can save your medicine scan history so you can access it later. Would you like to continue?” Display the explanation in large text. User says “Yes,” “No,” or “Tell me more.” If the user says “Tell me more,” speak and display the full explanation. 6. VOICE-ONLY HOME: The home screen should visually show the major functions, but the user never taps them. Display large options: SCAN MEDICINE, MY MEDICINES, VOICE HELP, CAREGIVER, SETTINGS. The app continuously listens for commands when appropriate. Example: user says “Scan medicine.” The app immediately opens the camera. User says “Show my medicines.” The history opens. User says “Help.” Voice help opens. 7. VOICE CAMERA CONTROL: When scanning starts, automatically open the camera without requiring a tap. Say and display: “Place the medicine strip in front of the camera.” Give live voice guidance: “Move closer,” “Move away,” “Move left,” “Move right,” “Move to the center,” “Hold steady,” “The lighting is too bright,” “The medicine is blurry.” The user controls the entire camera using voice. Commands include “Take photo,” “Scan,” “Retake,” “Scan back,” “Use this photo,” “Cancel.” No touch is required. 8. AUTOMATIC SCANNING: When the medicine is correctly positioned, optionally capture automatically. Display a camera preview and speak the status. Show: Reading medicine text → Identifying medicine → Checking expiry → Verifying information. 9. FRONT + BACK SCAN: If additional information is needed, automatically say: “Please turn the medicine strip over. I need to scan the other side.” The user turns it over and says “Ready.” The app captures the second image. No button tapping. 10. IMAGE QUALITY: Automatically detect blur, glare, poor lighting, orientation, and incomplete medicine visibility. If unclear, say and display: “I cannot read this image clearly. Please hold the medicine steady and try again.” The user says “Try again.” 11. MEDICINE IDENTIFICATION: Use multiple pieces of evidence such as medicine name, strength, active ingredient, manufacturer, packaging text, printed markings, and verified medicine database information. Never guess. Display and speak the verification status. HIGH CONFIDENCE: “This medicine has been identified successfully.” NEEDS VERIFICATION: “Some information is unclear. Please scan the other side.” NOT IDENTIFIED: “I could not reliably identify this medicine.” User can say “Scan again,” “Scan other side,” or “Cancel.” 12. MEDICINE RESULT: After reliable identification, display and speak: Medicine Name, Active Ingredient, Strength, Expiry Status, General Use, Age Information, Pregnancy/Breastfeeding Information, Important Warnings. Do not make the user tap Listen. The app automatically speaks the information. After speaking, ask: “Would you like more information?” User answers by voice. 13. NATURAL VOICE QUESTIONS: The user can ask naturally: “What is this medicine used for?” “What are the side effects?” “Is it expired?” “Can pregnant women use it?” “Tell me more.” “What are the warnings?” “Show my previous medicines.” The app understands the spoken question, displays the answer, and speaks it aloud. No typing. 14. EXPIRY: Automatically read expiry information from the medicine package using OCR and date validation. Display and speak: NOT EXPIRED, EXPIRING SOON, or EXPIRED. If expired, say: “Warning. This medicine appears to be expired. Please check with a pharmacist or healthcare professional before using it.” If expiry cannot be verified, say: “I could identify the medicine, but I could not verify the expiry date. Please scan the other side or original package.” Never guess an expiry date. 15. MEDICINE HISTORY: User says “Show my medicine history.” The app displays saved medicines and reads them aloud. User can ask: “What medicine did I scan yesterday?” “What did I scan last?” “Show expired medicines.” “Which medicines expire soon?” The app answers entirely through voice while displaying the results. 16. VOICE MEDICINE DETAILS: User says the medicine name or says “Open the last medicine.” The app displays and speaks the medicine details. The user can say “Tell me the side effects,” “Tell me the warnings,” “Tell me about pregnancy,” “Tell me about age restrictions,” “Generate report,” or “Delete this.” 17. CAREGIVER MODE: User says “Open caregiver mode.” The app uses secure voice-assisted authentication. Display caregiver information and speak it aloud. Caregiver access must require authorization and must not automatically expose the user's complete medical history. 18. EXPIRY NOTIFICATIONS: Automatically monitor verified expiry dates. Display and speak notifications such as: “This medicine will expire soon.” or “This medicine has expired.” Never notify based on an unverified expiry date. 19. PDF REPORT: User says “Generate medicine report.” The app generates a report containing medicine name, active ingredient, strength, expiry, uses, warnings, age information, pregnancy/breastfeeding information, side effects, storage, scan date, sources, and verification status. The app says: “Your medicine report is ready.” User can say “Open report,” “Share report,” “Read report,” or “Cancel.” 20. VOICE SETTINGS: User says “Open settings.” Settings are controlled entirely by voice. User can say: “Increase text size,” “Make text larger,” “Slow down voice,” “Turn on high contrast,” “Turn on vibration,” “Change language,” “Turn off voice guidance,” etc. The app confirms every change aloud and displays the new setting. 21. ERROR HANDLING: Every error must be communicated through both voice and display. Examples: “I couldn't understand you. Please say that again.” “I couldn't read the medicine.” “The medicine could not be identified reliably.” “The expiry date could not be verified.” “Internet connection is required for this information.” The user responds by voice. 22. NO-TOUCH PRINCIPLE: The entire product prototype must visually communicate that touch is optional/not required. Do not design workflows that depend on tapping buttons. Buttons may appear as visual indicators, but voice commands activate them. Every action, navigation step, confirmation, search, camera action, history action, setting, report action, and help function must have a voice command. 23. VISUAL DESIGN: Use a clean, trustworthy healthcare accessibility design. Large typography, high contrast, simple icons, clear visual feedback, microphone/listening indicator, voice waveform, medicine imagery, large status cards, accessible spacing, minimal clutter, and calm professional styling. The interface should always show what the app is hearing, what it understood, what it is doing, and what it is saying. 24. VOICE STATE UI: Create clear visual states for Listening, Understanding, Processing, Speaking, Waiting for Response, Error, and Success. Use a prominent microphone/voice indicator rather than conventional navigation controls. 25. FINAL EXPERIENCE: The finished application must feel like a voice-controlled medicine assistant, not a normal touchscreen healthcare app. A user should be able to complete the entire journey—from opening the app, selecting language, creating a profile, scanning medicine, identifying it, checking expiry, asking questions, viewing history, generating reports, changing settings, and accessing caregiver features—without typing or touching the screen at any point. Everything the app displays must also be spoken aloud, and everything the user needs to do must be possible through natural voice commands.
